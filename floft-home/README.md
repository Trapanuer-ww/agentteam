# F-LOFT — новая главная (прототип, 2026-10-06)

Статическая страница без сборки и библиотек. На f-loft.ru **не выложена**: живой сайт — WordPress (тема Impreza, WPBakery, Contact Form 7), его код в этот репозиторий не входит.

## Как посмотреть

Открытая ссылка для просмотра: https://trapanuer-ww.github.io/agentteam/ (ветка `gh-pages`, закрыта от индексации, форма не отправляет заявки).
При правках менять метку версии `?v=…` у `css/home.css` и `js/home.js` в `index.html`, иначе браузер может взять старый файл из кэша.

Локально:

```bash
python3 -m http.server 8791 --directory floft-home
# http://127.0.0.1:8791/            — с плашкой cookie
# http://127.0.0.1:8791/?cookie=0   — без неё (для скриншотов)
```

Открывается и просто двойным кликом по `index.html`.

## Состав

```
index.html        разметка, блоки подписаны комментариями
css/home.css      все стили; цвета и отступы — в :root в начале файла
js/home.js        шапка, меню, попап и форма, отзывы, появление блоков, плавающая кнопка, cookie
assets/img        фото в AVIF + WebP, несколько ширин на каждый кадр
assets/fonts      Tenor Sans (заголовки) и Mulish (текст), кириллица + латиница, локально
```

Порядок блоков: шапка → первый экран → 3 УТП → портфолио → форматы и вместимость → отзывы → «Приезжайте посмотреть» → подвал. Первый экран намеренно ниже окна браузера: снизу выглядывают три крупные строки УТП. На телефоне — плавающая кнопка «Оставить заявку».

## Форма

В прототипе форма **ничего не отправляет** (атрибут `data-demo` у `<form>`), после проверки показывает экран «Заявка отправлена» с пометкой «Прототип».

Разметка повторяет Contact Form 7 №114286 — попап «Оставить заявку» на живом сайте. Имена полей те же: `your-name`, `your-phone`, `your-date`, `textarea-900`, `acceptance-226` (×2), `kc_honeypot`.

При переносе на сайт:

1. Вместо `<form … data-demo>` вставить шорткод формы 114286. Стили `.modal .wpcf7 …` из `css/home.css` оформят вывод плагина; блок `if (form.hasAttribute('data-demo'))` в `js/home.js` перестанет срабатывать сам.
2. Экран «Заявка отправлена» включается по штатному событию плагина `wpcf7mailsent` — обработчик уже есть в `js/home.js`. Цели Метрики на отправку формы от этого не меняются.
3. Поле «Сообщение» (`textarea-900`) в форме остаётся, но скрыто. В него скрипт пишет, с какой кнопки пришла заявка: «Запись на просмотр площадки», «Запрос цены и особенностей зала» или «Заявка с плавающей кнопки (моб.)». Менеджер увидит это там же, где раньше видел сообщение клиента.
4. В настройках формы поле даты сейчас обязательное (`[date* your-date]`). В прототипе оно подписано «если известна» — чтобы так и работало, звёздочку в шаблоне формы нужно убрать. Если оставить обязательным — убрать подпись «если известна».
5. Маска телефона: на живом сайте значение `+7 (___) ___-__-__` лежит в `value` поля. Здесь маска написана заново (поле пустое до ввода, принимает 8…, +7…, вставку из буфера). Старый скрипт маски для этой формы нужно отключить, иначе они будут конфликтовать.
6. Видимой проверки «выберите картинку» в макете нет — убрана по решению заказчика. На сайте для этого из шаблона формы нужно убрать тег проверки плагина. Невидимое поле-ловушка `kc_honeypot` оставлено; если после переноса пойдёт спам, ставить невидимую защиту (без действий со стороны посетителя).

Как заявка из Contact Form 7 попадает в Битрикс24, по коду страницы не видно: скриптов Битрикс на главной нет, передача идёт на стороне сервера. Имена полей не менялись, поэтому связка не затрагивается — но проверить её можно только тестовой заявкой на сайте.

## Что убрать перед публикацией

- `<meta name="robots" content="noindex, nofollow">` в `<head>`.
- `og:image` сейчас указывает на локальный `assets/img/og.jpg` — заменить на полный адрес.
- Пометку «Прототип: форма не подключена…» (блок `.modal__demo`).
